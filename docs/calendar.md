# Календарь инвестора

> Блок «Календарь инвестора» на главной странице. Данные загружаются админом вручную через `POST /api/admin/calendar`. Располагается в самом низу `Home.tsx` после всех остальных блоков.

---

## Обзор

Календарь показывает ближайшие корпоративные события по рынку:

- отчётности (МСФО / РСБУ);
- собрания акционеров (СД);
- советы директоров (СА);
- дивиденды;
- другие события.

Данные загружаются единым снапшотом, бэкенд отдаёт плоский список строк, а фронтенд группирует их по дням и типам.

## Типы

Файл: `src/types/calendar.ts`.

```ts
export type EventKind = 'МСФО' | 'РСБУ' | 'СД' | 'СА' | 'Дивиденды' | 'Другое'
export type EventStatus = 'confirmed' | 'expected'

export interface CalendarCompany {
  name: string
  ticker: string
}

export interface CalendarEventGroup {
  title: string
  kind: EventKind
  status: EventStatus
  companies: CalendarCompany[]
}

export interface CalendarDay {
  date: string      // YYYY-MM-DD
  weekday: string   // 'пн'..'вс'
  groups: CalendarEventGroup[]
}

export interface CalendarResponse {
  server_date: string    // YYYY-MM-DD по московскому времени
  generated_at: string   // ISO timestamp загрузки снапшота
  stale: boolean         // true, если данные устарели
  days: CalendarDay[]
}
```

## API-обёртка

Файл: `src/lib/calendarApi.ts`.

```ts
export async function getCalendar(): Promise<CalendarResponse>
```

- Делает `GET /calendar` через общий `api.ts`.
- Если бэкенд вернул `503 { error: 'calendar_not_loaded' }`, ошибка пробрасывается как есть (`status === 503`, `message === 'calendar_not_loaded'`).
- Любая другая ошибка заворачивается в `calendarCopy.error`.

Кэширование: React Query `queryKey: ['calendar']`, `staleTime: 5 мин`, `gcTime: 30 мин`.

## Компонент `CalendarBlock`

Файл: `src/components/CalendarBlock.tsx`.

### Пропсы

| Проп | Тип | Описание |
|------|-----|----------|
| `portfolio` | `PortfolioTag[]` | Теги пользователя; нужны для подсветки компаний из портфеля. |

### Состояния

| Состояние | Когда показывается |
|-----------|--------------------|
| `isLoading` | `CalendarSkeleton` — серый плейсхолдер. |
| `isError && status === 503 && message === 'calendar_not_loaded'` | Блок полностью скрыт (снапшот ещё не загружен). |
| `isError` другой | Карточка с текстом `calendarCopy.error` и кнопкой «Повторить». |
| `data` получен | Полный UI: шапка, лента дат, фильтры, события. |
| `data.stale === true` | Жёлтый баннер «Данные устарели». |

### Лента дат

- Горизонтальный scrollable список дней из ответа бэкенда.
- Поддерживает drag мышью и touch.
- При клике по дню она становится выделенной, скролл подстраивается, чтобы выбранная дата оказалась по центру.
- Текущий день (`server_date`) обведён полупрозрачной голубой рамкой.
- Выбранный день — голубая подсветка + glow.
- Под каждой датой — точки цветами типов событий.
- Если в день есть компания из портфеля пользователя — внизу длинная голубая/зелёная полоса.
- Выходные дни отображаются приглушённым цветом.

### Выбор даты по умолчанию

Логика в `findDefaultDate(days, serverDate)`:

1. Если в снапшоте есть `server_date` — выбран сегодня.
2. Иначе — ближайшая будущая дата.
3. Иначе — последняя доступная дата.

### Фильтры

Кнопки-фильтры по типу события:

- `Все` (все группы);
- `МСФО`, `РСБУ`, `СД`, `СА`, `Дивиденды`, `Другое`.

Выбранный фильтр сохраняется в `localStorage` (`pulse_calendar_filter`).

Если для выбранного дня нет событий выбранного типа — показывается `calendarCopy.emptyFilter`.

### Группы событий

Каждая группа рендерится карточкой:

- Бейдж типа события цветом `KIND_COLORS`.
- Заголовок события.
- Бейдж статуса: `confirmed` → «подтверждено» (зелёный), `expected` → «ожидается» (жёлтый).
- Список компаний с тикерами.
- Компании из портфеля пользователя подсвечиваются голубым и помечаются бейджем «в портфеле».
- Если компаний больше 6 — показываются первые 6 и кнопка «ещё N ▾»; при раскрытии — «свернуть ▴».

### Подсветка портфеля

Логика в `src/lib/calendarMatch.ts`.

Правила совпадения (первое выполнившееся):

1. Точное совпадение тикера: `tag_id.toUpperCase() === company.ticker`.
2. Точное совпадение нормализованного названия: `normalizeName(tag_name) === normalizeName(company.name)`.

Нормализация: lower-case, trim, удаление кавычек/ёлочек, удаление юридических форм `ПАО` / `АО`.

> Пока **нет** fuzzy/substring matching. Тикеры работают надёжнее названий.

### Аналитика

| Событие | Когда |
|---------|-------|
| `calendar_match_rate` | Один раз за сессию: сколько компаний календаря есть в портфеле. |
| `calendar_day_select` | Клик по дате в ленте. |
| `calendar_filter_change` | Переключение фильтра. |
| `calendar_group_expand` | Раскрытие длинного списка компаний. |
| `calendar_company_click` | Клик по компании (передаётся `ticker`, `kind`, `in_portfolio`). |
| `calendar_refresh_click` | Клик по кнопке «Обновить». |

### SSE-обновление

Файл: `src/hooks/useSseNews.ts`.

Слушает событие `calendar:refresh` от бэкенда и инвалидирует кэш:

```ts
queryClient.invalidateQueries({ queryKey: ['calendar'] })
```

Это позволяет обновлять календарь у всех активных клиентов сразу после админской загрузки нового снапшота.

## Edge cases

- **Снапшот не загружен** — блок не рендерится (503 не показывается пользователю).
- **Пустой выбранный день** — текст «На этот день событий нет».
- **Нет событий выбранного типа** — текст «Событий этого типа нет».
- **Сегодня нет событий, но выбрана другая дата** — показывается подсказка «Сегодня событий нет — ближайшие:».
- **Данные устарели** (`stale === true`) — жёлтый баннер; бэкенд также шлёт админам Telegram-алерт раз в сутки.
- **Ошибка сети** — карточка с кнопкой повтора; лента дат остаётся кликабельной после успешного retry.
