# Календарь инвестора

> Блок «Календарь инвестора» на главной странице и админская вкладка для его управления. Данные загружаются админом через `/admin` → вкладка **Календарь**. Блок располагается в самом низу `Home.tsx` после всех остальных блоков.

---

## Обзор

Календарь показывает ближайшие корпоративные события по рынку:

- отчётности (МСФО / РСБУ);
- собрания акционеров (СД);
- советы директоров (СА);
- дивиденды;
- другие события.

Данные хранятся на бэкенде в двухслойной модели: сырые срезы провайдеров (`calendar_events_raw`) и канонический дедуплицированный срез (`calendar_events`). Бэкенд отдаёт клиентам готовый сгруппированный снапшот.

## Типы

Файл: `src/types/calendar.ts`.

```ts
export type EventKind = 'МСФО' | 'РСБУ' | 'СД' | 'СА' | 'Дивиденды' | 'Другое'
export type EventStatus = 'confirmed' | 'expected'

export interface CalendarCompany {
  name: string
  ticker: string
}

export interface CalendarEventGroup {
  title: string
  kind: EventKind
  status: EventStatus
  companies: CalendarCompany[]
}

export interface CalendarDay {
  date: string      // YYYY-MM-DD
  weekday: string   // 'пн'..'вс'
  groups: CalendarEventGroup[]
}

export interface CalendarResponse {
  server_date: string    // YYYY-MM-DD по московскому времени
  generated_at: string   // ISO timestamp загрузки снапшота
  stale: boolean         // true, если данные устарели
  days: CalendarDay[]
}

export interface CalendarAdminEvent {
  date: string      // YYYY-MM-DD
  weekday: string
  title: string
  kind: EventKind
  status: EventStatus
  companies: CalendarCompany[]
  companies_count: number
  sources?: string[]
  tag_ids?: string[]
  possible_duplicate?: boolean
}
```

> Поля `sources` и `tag_ids` приходят от бэкенда в admin-ответах; в текущей версии UI они не рендерятся в таблице напрямую, но доступны для доработок (например, бейджи источников или тегов).

## API-обёртка

Файл: `src/lib/calendarApi.ts`.


- Любая другая ошибка заворачивается в `calendarCopy.error`.

## Компонент `CalendarBlock`

Файл: `src/components/CalendarBlock.tsx`.

### Пропсы

| Проп | Тип | Описание |
|------|-----|----------|
| `portfolio` | `PortfolioTag[]` | Теги пользователя; нужны для подсветки компаний из портфеля. |

### Состояния

| Состояние | Когда показывается |
|-----------|--------------------|
| `isLoading` | `CalendarSkeleton` — серый плейсхолдер. |
| `isError && status === 503 && message === 'calendar_not_loaded'` | Блок полностью скрыт (снапшот ещё не загружен). |
| `isError` другой | Карточка с текстом `calendarCopy.error` и кнопкой «Повторить». |
| `data` получен | Полный UI: шапка, лента дат, фильтры, события. |
| `data.stale === true` | Жёлтый баннер «Данные устарели». |

### Лента дат

- Горизонтальный scrollable список дней из ответа бэкенда.
- Поддерживает drag мышью и touch.
- При клике по дню она становится выделенной, скролл подстраивается, чтобы выбранная дата оказалась по центру.
- Текущий день (`server_date`) обведён полупрозрачной голубой рамкой.
- Выбранный день — голубая подсветка + glow.
- Под каждой датой — точки цветами типов событий.
- Если в день есть компания из портфеля пользователя — внизу длинная голубая/зелёная полоса.
- Выходные дни отображаются приглушённым цветом.

### Выбор даты по умолчанию

Логика в `findDefaultDate(days, serverDate)`:

1. Если в снапшоте есть `server_date` — выбран сегодня.
2. Иначе — ближайшая будущая дата.
3. Иначе — последняя доступная дата.

### Фильтры

Кнопки-фильтры по типу события:

- `Все` (все группы);
- `МСФО`, `РСБУ`, `СД`, `СА`, `Дивиденды`, `Другое`.

Выбранный фильтр сохраняется в `localStorage` (`pulse_calendar_filter`).

Если для выбранного дня нет событий выбранного типа — показывается `calendarCopy.emptyFilter`.

### Группы событий

Каждая группа рендерится карточкой:

- Бейдж типа события цветом `KIND_COLORS`.
- Заголовок события.
- Бейдж статуса: `confirmed` → «подтверждено» (зелёный), `expected` → «ожидается» (жёлтый).
- Список компаний с тикерами.
- Компании из портфеля пользователя подсвечиваются голубым и помечаются бейджем «в портфеле».
- Если компаний больше 6 — показываются первые 6 и кнопка «ещё N ▾»; при раскрытии — «свернуть ▴».

### Подсветка портфеля

Логика в `src/lib/calendarMatch.ts`.

Правила совпадения (первое выполнившееся):

1. Точное совпадение тикера: `tag_id.toUpperCase() === company.ticker`.
2. Точное совпадение нормализованного названия: `normalizeName(tag_name) === normalizeName(company.name)`.

Нормализация: lower-case, trim, удаление кавычек/ёлочек, удаление юридических форм `ПАО` / `АО`.

> Пока **нет** fuzzy/substring matching. Тикеры работают надёжнее названий.

## Edge cases

- **Снапшот не загружен** — блок не рендерится (503 не показывается пользователю).
- **Пустой выбранный день** — текст «На этот день событий нет».
- **Нет событий выбранного типа** — текст «Событий этого типа нет».
- **Сегодня нет событий, но выбрана другая дата** — показывается подсказка «Сегодня событий нет — ближайшие:».
- **Данные устарели** (`stale === true`) — жёлтый баннер; бэкенд также шлёт админам Telegram-алерт раз в сутки.
- **Ошибка сети** — карточка с кнопкой повтора; лента дат остаётся кликабельной после успешного retry.

## Админка: вкладка «Календарь»

Файл: `src/pages/admin/CalendarTab.tsx`.

Вкладка состоит из трёх частей:

1. **Шапка** — статус снапшота, кнопка обновления, рубильник LLM-матчинга, кнопка «Загрузить снапшот».
2. **Модуль загрузки среза** — загрузка raw-файла провайдера через бэкенд-адаптер.
3. **Таблица событий** — просмотр, фильтрация, создание, редактирование и удаление групп.

### Шапка

```tsx
<div className="flex items-center gap-3">
  {/* LLM toggle */}
  <label className="relative inline-flex items-center cursor-pointer select-none">
    <input
      type="checkbox"
      className="sr-only peer"
      checked={llmEnabled ?? true}
      onChange={handleToggleLlm}
      disabled={llmLoading || llmEnabled === null}
    />
    <span className="ml-2 text-xs" style={{ color: '#9CA3AF' }}>
      LLM-матчинг тегов
    </span>
  </label>
  ...
</div>
```

- Переключатель читает текущее состояние из `GET /api/admin/calendar/settings`.
- При изменении шлёт `PUT /api/admin/calendar/settings` с `{ llm_enabled: boolean }`.
- Состояние влияет на матчинг тегов при следующей пересборке канона.

### Загрузка среза провайдера

- Показывает текущий статус: загружен ли снапшот, сколько дней и компаний.
- Кнопка **Загрузить снапшот** открывает модалку.
- В модалке:
  - `input type="file"` для JSON.
  - Поддерживаемые форматы: raw `investmint_calendar.json` и `smartlab_calendar.json`.
  - **Предпросмотр** — сразу после выбора файла фронт парсит файл локально (теми же функциями, что используют бэкенд-адаптеры) и показывает статистику: количество дней, событий, компаний, период, записи без тикера, пропущенные строки. Файл не уходит на сервер, пока админ не нажмёт «Загрузить».
  - **Автоопределение источника** — при загрузке файл отправляется на `POST /api/admin/calendar/auto`. Бэкенд выбирает адаптер (`investmint` или `smartlab`), парсит, нормализует, пишет в `calendar_events_raw` и пересобирает канон.
  - Загрузка **заменяет** предыдущий срез этого источника. Другие источники не трогаются. Дедупликация и приоритеты применяются на бэкенде.

**Запрос загрузки:**

```ts
await adminApi.post('/api/admin/calendar/auto', rawPayload)
```

где `rawPayload` — оригинальный распарсенный JSON файла (массив investmint/smartlab).

**Ответ бэкенда:**

```json
{
  "parsed": { "days": 5, "events": 12, "warnings": [] },
  "diff": {
    "new_events": 10,
    "updated_events": 0,
    "confirmed_upgrades": 0,
    "confirmations": 2,
    "removed_events": 0
  },
  "samples": { "new": [...], "removed": [], "upgraded": [] },
  "generated_at": "2026-08-30T10:00:00.000Z"
}
```

#### Парсинг `smartlab_calendar.json` (preview-only)

Файл: `src/pages/admin/CalendarTab.tsx` → `parseSmartlabCalendar`.

**Ожидаемая структура:**

```json
[
  { "date": "28.08.2026", "time": "10:30", "title": "MGKL: Трансляция о результатах МСФО за 1п 2026г", "text": "..." },
  { "date": "31.08.2026", "time": "", "title": "BELU: СД рассмотрит вопрос о промежуточных дивидендах", "text": "..." }
]
```

**Логика (preview):**

1. **Дата** — парсится из `ДД.ММ.ГГГГ`, год берётся прямо из файла.
2. **Тикер** — вытаскивается из начала `title` по паттерну `TICKER:` или `TICKER - `.
3. **Название компании** — обычно совпадает с тикером (`name === ticker`). Это ограничение формата smartlab.
4. **Тип** — `detectKind` по оставшемуся тексту заголовка.
5. **Статус** — `detectStatus` (`confirmed`/`expected`).
6. **Группировка** — события с одинаковой датой, заголовком и типом объединяются; компании (тикеры) дедуплицируются.

> **Записи без тикера:** если в `title` не найден тикер, событие сохраняется с `ticker = 'UNKNOWN'` и `name = fullTitle`. В preview админ видит количество таких записей.

#### Парсинг raw-формата `investmint_calendar.json` (preview-only)

Файл: `src/pages/admin/CalendarTab.tsx`.

Для каждой строки raw-формата:

1. **Дата** — парсится из строки вида `"1 января пн"`.
   - Год **не указан в файле**, поэтому вычисляется эвристикой `inferYear`:
     - берётся текущий месяц;
     - если месяц события строго меньше текущего → год = текущий + 1;
     - иначе → текущий год.
   - На бэкенде эвристика усилена совпадением дня недели (`inferYearWithWeekday`), поэтому боевые данные могут отличаться от preview на редких файлах.

2. **Тип события (`detectKind`)** — определяется по ключевым словам:
   - `совет директоров` или отдельное слово `сд` → `СД`;
   - `госа`, `воса`, `собрание акционеров`, `собрание` → `СА`;
   - `мсфо` → `МСФО`;
   - `рсбу` → `РСБУ`;
   - `дивиденд` → `Дивиденды` (проверка идёт после `СД`);
   - всё остальное → `Другое`.

3. **Статус (`detectStatus`)**:
   - `ожидается` или `предварительно` → `expected`;
   - остальное → `confirmed`.

4. **Компании** — каждый токен разбивается по регулярке `COMPANY_RE` (буква рейтинга + название + тикер латиницей).

#### Почему именно `/api/admin/calendar/...`?

В проекте два семейства админ-роутов:

| Семейство | Путь | Примеры |
|-----------|------|---------|
| Legacy | `/admin/...` | `/admin/llm-dashboard`, `/admin/tags`, `/admin/backfill` |
| Новые | `/api/admin/...` | `/api/admin/users`, `/api/admin/plans`, `/api/admin/calendar` |

`adminApi` в `src/lib/api.ts` использует базовый URL без `/api`, поэтому для новых роутов нужно указывать полный путь **с префиксом `/api/admin/`**:

```ts
// правильно
await adminApi.post('/api/admin/calendar/auto', rawPayload)
await adminApi.post('/api/admin/calendar/events', event)

// неправильно (404 — такого legacy-роута нет)
await adminApi.post('/admin/calendar/events', event)
```

### Редактор события

Файл: `src/components/admin/CalendarEventModal.tsx`.

Модалка работает в двух режимах: **создание** (`event === null`) и **редактирование**.

**Поля формы:**

| Поле | Описание |
|------|----------|
| Дата | `input type="date"`. При изменении автоматически вычисляется день недели. |
| День недели | текстовое поле, можно отредактировать вручную. |
| Заголовок | текст события. |
| Тип | селект из `EventKind`. |
| Статус | `confirmed` / `expected`. |
| Компании | список пар `название + тикер`, можно добавлять и удалять строки. |

**Логика редактирования:**

1. При открытии модалки в режиме редактирования делается `GET /api/admin/calendar/events/:date/:title/:kind`.
2. В ответе приходит полная группа со списком компаний.
3. Форма заполняется полученными данными.
4. При сохранении отправляется `PUT` на тот же путь с телом нового состояния.
5. Редактор позволяет изменить `date`/`title`/`kind`; бэкенд удалит старую группу и создаст новую.

**Валидация на клиенте:**

- Обязательны дата, заголовок, тип, статус.
- Должна быть хотя бы одна заполненная компания (`name` + `ticker`).
- Тикеры внутри одной группы не должны повторяться (проверка `toUpperCase()`).

**Сохранение:**

- `POST /api/admin/calendar/events` — для новой группы.
- `PUT /api/admin/calendar/events/:date/:title/:kind` — для существующей.

После успешного сохранения:

- модалка закрывается;
- обновляется статус снапшота в `CalendarTab`;
- таблица перезагружается через `refreshSignal`;
- SSE `calendar:refresh` автоматически обновит календарь у всех активных клиентов.

---

### Удалённые события (tombstones)

Tombstone-записи возвращаются через `GET /api/admin/calendar/events?tombstones=true`. Восстановление — `DELETE /api/admin/calendar/events/tombstone` с query-параметрами `date`, `title`, `company`, `original_title`.
