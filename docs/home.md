# Главная страница

`src/pages/Home.tsx` — главная страница приложения.

## Структура

1. `FreezeTagsBanner` — баннер заморозки / превышения лимита тегов (если есть условия).
2. `Hero` — поиск, облако тегов, счётчик, PulseLine.
2а. `DemoTagsRow` — демо-теги под поиском в hero (только гостям — ТЗ-59). Чипы в стиле компонента `Tag` (те же цвета по типам), read-only: клик по любому → модалка регистрации (`openAuthModal('register')`). Источник — `GET /api/public/demo-tags` (кэш 60 с). Ошибка/пусто → блок скрыт. Демо-аккаунт: env `PUBLIC_DEMO_EMAIL` (дефолт `vladfa@ya1.ru`) — владелец наполняет тегами сам, контент лендинга правится без деплоя; замороженные теги не отдаются.
3. `DailySummary` — AI daily summary по тегам пользователя.
4. `GlobalSummary` — AI summary всей новостной ленты за последние 6 часов (авторизованным; гостям — публичный режим, см. 15а).
5. `UnreadNewsCarousel` — "Это вы ещё не видели".
6. `AllNewsCarousel` — вся лента по тегам.
7. `BlurHighlight` — текст-объяснение над демо-лентой (только гостям — ТЗ-68). Компонент `@reactbits-starter/blur-highlight-tw` (`src/components/react-bits/blur-highlight.tsx`, импорты переведены на `framer-motion`, пакет `motion` не используется). Текст проявляется из блюра при входе во вьюпорт (`once: true`), 4 фразы подсвечиваются cyan sweep-ом слева направо. Текст и фразы — константы `DEMO_FEED_TEXT`/`DEMO_FEED_BITS` в `Home.tsx` (фразы BITS обязаны быть точными подстроками TEXT). При `prefers-reduced-motion` — статичный текст. Заменил бывший subtitle в hero «Акции. Секторы. Личности. Тренды…».
8. `DemoFeedCarousel` — демо-лента с графиками (только гостям, сразу под hero — ТЗ-59, кэш — ТЗ-60). Лента демо-аккаунта (`GET /api/public/demo-feed`, **без пагинации**: бэкенд игнорирует query-параметры, отдаёт первые 50 новостей, кэш 60 с одним ключом на весь ответ, в ответе `page: 1`, `hasMore: false`, `cached_at`), карточки `NewsCard` с `showChart` — график реакции рынка запрашивается только когда карточка во вьюпорте. Один запрос через `useQuery` (sentinel/бесконечный скролл убраны — ТЗ-60). Ошибка/пусто → блок скрыт.
9. `GlobalNewsCarousel` — общая лента (только авторизованным; с гостевой главной убрана — гостю вместо неё демо-лента, п. 8).
10. `PublicInfoVolume` — «Объём информации» эталонного аккаунта (только гостям, выше баннера «Суперсила» — ТЗ-56). Вёрстка 1:1 с профилем (glass-карта, зелёный акцент #10B981, сетка 2×2), данные — `GET /api/public/efficiency` (публичный; кэш на сутки, ленивый пересчёт + прогрев после boot — ТЗ-57, эталонный аккаунт через env `PUBLIC_EFFICIENCY_EMAIL`). Подзаголовок «обновляются ежедневно» соответствует реальности кэша. Ошибка/404 → блок молча скрыт.
11. `SuperpowerVideoBanner` — видео-баннер «Суперсила инвестора — знать» (только гостям, под «Объёмом информации» — ТЗ-55). Фоновое зацикленное видео (`public/media/hero-video-2.mp4`), ленивая загрузка через IntersectionObserver (пока не доскроллил — сетевого запроса нет), pause/play при уходе/возврате в viewport, градиент-заглушка при ошибке, `prefers-reduced-motion` — без видео и пульса. CTA «Получить суперсилу» открывает модалку регистрации (`AuthModalContext`), аналитика: `home_superpower_view` / `home_superpower_cta_click`.
12. `SentimentChartCard` — индекс настроения. Блок вынесен в модульный компонент `HomeSentimentIndex` (тот же JSX, Suspense + скелетон). Авторизованным — после `PublicInfoVolume`; гостям — сразу после `CalendarBlock` (календарь инвестора).
13. `TelegramConnectBanner` — промо-баннер Telegram.
14. `PopularTagsSlider` — популярные теги. Авторизованным — после Telegram-баннера; гостям — самый низ страницы (после календаря).
15. Блок «Портфель инвестиционно.рф» (только авторизованным — с гостевой главной убран).
16. `FeaturesCarousel` — «Что Pulse делает вместо вас», карусель из 7 карточек поверх общей оболочки `NewsCarousel` (стрелки по 450px, нативный скролл/свайп, боковые затемнения; карточки 210px). Только гостям, сразу под hero. Первые 3 карточки («Хватит читать перепечатки», «Цена уже здесь», «Не верьте заголовку на слово») — видны без скролла; порядок — часть смысла. Компонент: `src/components/home/FeaturesCarousel.tsx`. Старая статичная сетка `FeatureCard` из Home.tsx удалена.
16а. `GlobalSummary isPublic` — «Пульс рынка»: ИИ-саммари всей ленты (до 200 новостей за 6 часов) для гостей, сразу под каруселью. Публичный режим компонента `GlobalSummary`: ходит в `GET /api/public/summary-global`, который отдаёт **только свежий кэш** (генерацию LLM не триггерит — прогрев кэша делает cron: warm-up через 3 мин после boot + каждые 6 ч). Кнопки «Обновить» у гостей нет; кэша нет/ошибка → блок молча скрыт. Вёрстка 1:1 с авторизованной версией (ширина как у карусели, `px-6`).
17. `CalendarBlock` — календарь инвестора.
18. `MarketPulseMini` — мини-блок «Пульс рынка» (тепловая карта активности). Публичный, скрывается при отсутствии новостей. Клик → `/activity-map?scope=all&scale=year`.
19. Второй hero «Ваши инструменты» — заголовок стилем основного hero (кегль `clamp(32px, 5.33vw, 64px)`, градиент + голубой курсив, та же анимация framer-motion). Только гостям, размещён над «Пульсом рынка».
20. CTA «Бесплатная регистрация» — чёрная кнопка (поверхность `#0E0E0E`, белый текст, pill-радиус, размер на 50% крупнее базового: `px-[30px] py-[15px] text-[21px]`) с эффектом BorderGlow (reactbits, MIT; порт: `src/components/BorderGlow.tsx`): светящаяся рамка из палитры cyan/зелёный/фиолет следует за курсором, а при появлении во вьюпорте (IntersectionObserver, порог 0.6) свечение пробегает по рамке; пробег повторяется при каждом возврате на экран, не стартует под курсором и пока предыдущий пробег не доиграл. Клик → `openAuthModal('register')` — модалка авторизации сразу на табе создания аккаунта (аналитика `open_auth_modal` срабатывает сама). Только гостям. Компонент `RegisterCta` (`Home.tsx`), дублируется в двух точках: **после ИИ-саммари** («Пульс рынка», п. 16а — конверсионная точка на прочитанном инсайте) и **в самом низу страницы** после `PopularTagsSlider` (там `bottom` → `pb-24`).

## Баннер заморозки тегов

Компонент: `src/components/FreezeTagsBanner.tsx`.

Показывается **первым после Hero/поиска**, если пользователь вошёл и выполнено одно из условий:

- есть замороженные теги (`frozen_tags > 0`);
- количество активных тегов превышает лимит effective-плана (`to_remove > 0`);
- баннер не был закрыт вручную крестиком в течение последних 24 часов (`localStorage.freezeBannerClosed`).

Effective-план вычисляется бэкендом (`buildSubscriptionStatus`): после окончания грейса лимит будет от `free`, даже если в БД `subscription_plan` всё ещё `'premium'`.

Если `tag_limit < 0` (безлимитный Premium), баннер не показывается.

#### Текст баннера

Заголовок зависит от состояния:

| Состояние | Заголовок |
|-----------|-----------|
| `frozen_tags > 0 && to_remove > 0` | "Теги заморожены — удалите лишние" |
| `frozen_tags > 0 && to_remove === 0` | "Замороженные теги — выберите активные или восстановите Premium" |
| `frozen_tags === 0 && to_remove > 0` | "У вас слишком много тегов для тарифа" |

Данные загружаются с `GET /api/user/tag-status`. Формат ответа:

| Поле | Тип | Описание |
|------|-----|----------|
| `current_plan` | string | ID effective-плана |
| `plan_name` | string | Отображаемое имя effective-плана |
| `tag_limit` | number | Лимит тегов (−1 = безлимит) |
| `total_tags` | number | Всего тегов (активных + замороженных) |
| `active_tags` | number | Активных тегов |
| `frozen_tags` | number | Замороженных тегов |
| `to_remove` | number | Сколько тегов нужно удалить, чтобы уложиться в лимит |
| `tags` | array | Список тегов с полями `id`, `tag_id`, `name`, `tag_type`, `is_frozen`, `news_count_30d` |

### Поведение

- **Крестик в правом верхнем углу** закрывает баннер на 24 часа (`localStorage.freezeBannerClosed`).
- **Каждый тег** — chip: имя + крестик, под ним "N новостей за 30 дней".
- **Клик по крестику на теге** вызывает удаление тега через `useAuth().removeTag()` (внутри — `DELETE /api/user/tags/:tagId` или аналогичный метод контекста). Chip анимирует исчезновение (scale + opacity). После успеха статус баннера перезагружается.
- **Кнопка сохранения**:
  - пока `to_remove > 0` — disabled, текст "Удалите N тегов";
  - когда `to_remove === 0` — активна, текст "Сохранить N тегов";
  - при нажатии отправляется `POST /api/user/select-active-tags` с телом `{ activeTagIds: [...] }` — массив `id` (не `tag_id`) всех тегов, отображаемых в баннере.
- **После успешного сохранения**:
  - баннер исчезает с анимацией `fade out + slide up` (400 ms, `framer-motion` `exit`);
  - не показывается `alert()` с подтверждением;
  - баннер **не** блокируется в `localStorage` на 24 часа — при повторном превышении лимита он появится снова после следующего `loadStatus()`.
- **Ошибки** отображаются inline красным текстом под списком тегов, не через `alert()`.
- Баннер обёрнут в `AnimatePresence`, поэтому exit-анимация отрабатывает корректно при полном unmount.
- **Обновление без перезагрузки:** баннер слушает событие `subscription:refresh` (диспатчится после оплаты/даунгрейда) и обновляется при `visibilitychange` (возврат во вкладку).

### Сценарий

```
1. Пользователь заходит на главную с 13 тегами, лимит = 10.
2. Баннер показывает 13 тегов, кнопка: "Удалите 3 тега".
3. Пользователь удаляет 3 тега крестиками — chip'ы анимируют исчезновение.
4. Кнопка меняется на "Сохранить 10 тегов" и становится активной.
5. Пользователь нажимает "Сохранить".
6. POST /api/user/select-active-tags → активные теги сохраняются, остальные замораживаются.
7. Баннер плавно исчезает (opacity → 0, translateY → −20px), пользователь остаётся на главной.
```
